# Domain: Messaging

## Overview
The messaging layer shared by channels and DMs. Covers message send/receive, thread replies (2-level nesting), reactions (toggle), message sharing/forwarding, and system messages.

## Key Files
| File | Role |
|---|---|
| `backend/src/routes/channels.ts` | Channel message endpoints + reactions + share |
| `backend/src/routes/dms.ts` | DM message endpoints + reactions |
| `frontend/src/components/MessageBubble.tsx` | Message render: reactions, thread opener, share button, linked task chip |
| `frontend/src/components/MessageActionBar.tsx` | Hover action bar (react, reply, share, create task) |
| `frontend/src/components/ThreadPanel.tsx` | Slide-in thread reply panel |
| `frontend/src/components/ShareModal.tsx` | Share-to-channel/DM modal |
| `frontend/src/components/EmojiPicker.tsx` | Emoji picker for reactions |
| `frontend/src/store/uiStore.ts` | `activeThreadId`, unread counters |

## Message Shape (`Message` type in `types.ts`)
```ts
{
  id, channel_id?, dm_thread_id?,
  sender_id, sender: User,
  content,
  created_at,
  parent_message_id: string | null,   // set for thread replies
  reply_count: number,
  reactions: Reaction[],               // [{ emoji, count, users: string[] }]
  linked_task_id?: string,
  linked_task?: Task,                  // hydrated task snapshot
  shared_message_id?: string,
  shared_message?: SharedMessagePreview,
  is_system: 0 | 1,                   // system messages (e.g. task assignment events)
}
```

## Thread Model
- Max **2 levels** of nesting: root → depth-1 reply → depth-2 reply (no deeper)
- Thread replies have `parent_message_id` set; root messages have it `null`
- Fetching threads: `GET .../thread/:messageId` returns depth-1 + depth-2 replies flattened and sorted by `created_at`
- Socket routing for thread replies: emitted to individual `user:{id}` rooms of thread participants (not the whole channel room), so only thread participants get the update

## Reactions
- Stored in `message_reactions (message_id, user_id, emoji)` — composite PK prevents duplicates
- Toggle: POST → exists? delete : insert
- After toggle, full reaction list is re-fetched and emitted via `reaction_updated`
- Aggregated as `[{ emoji, count, users: string[] }]` — `users` contains user IDs

## Message Sharing
- Creates a new message with `shared_message_id` pointing to the original
- Frontend renders `SharedMessagePreview` embed inside `MessageBubble`
- **Privacy constraint**: cannot share a private channel message to a public channel; recipient of DM share must be a member of the source private channel

## System Messages (`is_system = 1`)
- Auto-generated by backend (not user-authored)
- `content` is a JSON string payload — parse before rendering
- Triggered by: task assignment, task creation from message
- Rendered differently in `MessageBubble` (no action bar, distinct style)
- Should never be shown in `MessageActionBar`

## Mentions
- Pattern: `@username` in content
- Backend scans with regex, looks up user by name in workspace, inserts notification
- Emits `notification` to `user:{mentionedUserId}` room

## Socket Events (Messaging)
| Event | Room | Trigger |
|---|---|---|
| `new_message` | `channel:{id}` | New root message in channel |
| `new_message` | `user:{id}` | New thread reply (per participant) |
| `new_dm` | `dm:{threadId}` | New root DM message |
| `new_dm` | `user:{id}` | New DM thread reply (per participant) |
| `reaction_updated` | `channel:{id}` or `dm:{threadId}` | Reaction toggle |

## Constraints
- `content` is required for all messages — backend returns 400 if missing
- Messages load last **200** records, oldest first (`ORDER BY created_at ASC LIMIT 200`)
- Thread depth > 2 returns 400 — never attempt deeper nesting
- System message `content` is JSON — always try/catch parse before using
